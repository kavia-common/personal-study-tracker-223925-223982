# Database Container

This container is dedicated to running PostgreSQL only.

What this container does:
- Initializes and starts PostgreSQL on port 5001
- Binds to 0.0.0.0 and :: (listen_addresses='*') so it is reachable from other containers
- Creates database: myapp
- Creates user: appuser (password provided via environment or defaults for local dev)
- Writes connection helper to db_connection.txt
- Waits for readiness using pg_isready before exiting startup

What this container does NOT do:
- It does not start any Node.js servers. This prevents MODULE_NOT_FOUND errors during startup.

Optional: db_visualizer helper
- A simple Node-based viewer exists under Database/db_visualizer but is NOT part of this container's startup.
- It must be started manually if desired and only outside the Database container lifecycle.
- To use it locally (manual only):
  1) cd Database/db_visualizer
  2) source postgres.env (generated by startup.sh after DB starts)
  3) npm install
  4) npm start
- This runs a viewer on port 3000 and connects to the local PostgreSQL exposed via port 5001.

Connection info
- Host: localhost (or the service/container host)
- Port: 5001
- Database: myapp
- User: appuser
- Password: dbuser123 (or set via env DB_PASSWORD)
- Ready-to-copy command is written to db_connection.txt, e.g.:
  psql postgresql://appuser:dbuser123@localhost:5001/myapp

Health/Readiness
- The startup script waits for PostgreSQL readiness using pg_isready against 127.0.0.1:5001.
- You can manually verify with:
  sudo -u postgres /usr/lib/postgresql/<ver>/bin/pg_isready -h 127.0.0.1 -p 5001

Environment variables (optional overrides)
- DB_NAME (default: myapp)
- DB_USER (default: appuser)
- DB_PASSWORD (default: dbuser123)
- DB_PORT (default: 5001)

Networking
- PostgreSQL is configured with listen_addresses='*' and started with -h '*' so it listens on 0.0.0.0 and :: by default.

Troubleshooting
- If port 5001 is already in use, startup will exit with an error to prevent conflicts.
- Check /var/lib/postgresql/server.log for server output and pg_isready logs at /var/lib/postgresql/pg_isready.log.

Verification
- Ensure no Node.js processes are spawned by startup.sh (script intentionally contains no node/npm calls).
- After running startup.sh:
  - You should see lines similar to:
    [startup] Starting PostgreSQL server with port 5001 and listen on all interfaces...
    [startup] PostgreSQL is ready (attempt X).
    [startup] Verification:
      - No Node.js processes were started by this script.
      - PostgreSQL is listening on 0.0.0.0:5001 (and :: if enabled).
      - pg_isready on 127.0.0.1:5001: 127.0.0.1:5001 - accepting connections
- Confirm port binding:
  ss -lnt | grep ":5001"
- Exit status:
  echo $? should be 0 upon successful completion of startup.sh
